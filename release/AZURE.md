# Owner-operated APK signing with Azure Key Vault

Use a dedicated vault with Azure RBAC and purge protection. Review effective assignments at the key, vault, resource group and subscription levels. Grant signing access to the publisher's user identity only. Administrators who can change role assignments can still grant access. Protect the publisher account with phishing-resistant MFA. This project uses no GitHub Actions signing identity.

Create a self-signed RSA certificate in the vault with a non-exportable private key, the digitalSignature key usage and a long validity suitable for Android updates (for example, 30 years). Keep the original signing identity across versions. Avoid automatic certificate renewal or reissuance: a changed certificate can break updates even if the alias stays the same. Inspect the certificate's public DER file, calculate its SHA-256 fingerprint and record the 64 hexadecimal digits in release/app-signing-sha256.txt. The certificate fingerprint is public.

On your trusted Windows workstation, install Java, Android SDK Build Tools, Azure CLI and the official Jsign 7.6 all-in-one JAR from https://github.com/ebourg/jsign/releases/tag/7.6. The signing script checks the published JAR digest. Sign in with az login. Build the reviewed source with Gradle 8.5 using :app:assembleRelease. Pass the resulting zip-aligned unsigned release APK to Sign-AzureApk.ps1 along with OutputApk, VaultName, CertificateName, BuildTools and JsignJar. Sign only source and dependencies you have reviewed. Approving a signature on malicious code remains possible even when a key is non-exportable.

Publish the verified APK from your owner account on GitHub Releases. Use an increasing version code and a stable asset name, USB-Screensaver.apk. The verifier checks the installed Android signing trust model: the package must be the production app and have the enrolled signer. For a first installation, distribute the official release URL and the certificate fingerprint through a trusted channel. Existing test-signed installations ordinarily require a one-time reinstall when moving to the production signer.
